# 증권사 선택 검토 (메리츠증권 중심)

> 조사 시점: **2026-09**. API 정책은 자주 바뀌므로 도입 직전에 반드시 재확인할 것.

## 1. 메리츠증권

| 항목 | 내용 |
|---|---|
| 개인용 공개 REST/WebSocket API | **확인되지 않음** — 공개 개발자센터·API 문서 없음 |
| 업계 보도 (2026-05) | 오픈 API 개발을 사실상 마무리하고 **내부 테스트 중**, 연내 출시 관측 |
| 결합 예상 | 무수수료 `Super365` 계좌 |
| 자동매매 관점의 매력 | **수수료가 성과에 직결**되므로 무수수료 계좌 + API 조합은 실제로 강력하다 |
| 현재 결론 | **기다릴 가치는 있으나, 오늘 코드로 붙일 수 없다** |

### 확인 방법
1. 메리츠증권 고객센터 **1588-3400** 또는 거래 지점에 문의
   - "개인 고객용 오픈 API(REST) 제공 계획과 신청 절차"
   - "베타/사전 신청 프로그램 참여 가능 여부"
2. 메리츠증권 홈페이지 공지사항 주기적 확인

### 출시되면 할 일 (5분)
```bash
cp config/meritz.spec.example.json config/meritz.spec.json
# 공식 문서를 보고 TODO_ 값(경로·필드명·주문코드)을 채운다
AUTOTRADE_MODE=meritz python3 -m autotrade.cli doctor
AUTOTRADE_MODE=meritz python3 -m autotrade.cli quote --symbol 005930
```
`config/meritz.spec.json`은 `.gitignore`에 있으므로 커밋되지 않는다.

### 하지 말아야 할 우회
HTS/MTS 화면 매크로, 내부 웹 요청 리버스 엔지니어링은 **약관상 금지행위**에 해당할 수 있고
(계좌 이용 제한 사유), 규격 변경 시 주문이 조용히 실패하며, 사고 시 구제받기 어렵다.
자동매매에서 가장 비싼 실패는 "돈이 걸린 채 조용히 틀리는 것"이다.

## 2. 지금 실전 검증이 가능한 증권사

| 증권사 | 방식 | OS 제약 | 모의투자 | 비고 |
|---|---|---|---|---|
| **한국투자증권 (KIS)** | REST + WebSocket | 없음 (리눅스 서버 OK) | **있음 (별도 서버·별도 앱키)** | 개인 자동매매의 사실상 표준. 이 저장소가 구현한 대상 |
| 키움증권 | 전통 OpenAPI+는 Windows COM/OCX, 별도 REST 계열도 존재 | OpenAPI+는 Windows 필요 | 있음 | 사용자층이 두껍고 자료가 많다 |
| LS증권 | XingAPI(Windows) + 신규 OPEN API | 신규 API는 완화 | 있음 | 파생·야간 세션 강점 |
| 대신증권 | CREON Plus (COM) | Windows 전용 | 제한적 | HTS 상시 구동 필요 |

### 왜 이 저장소는 KIS를 기본 구현으로 골랐나
1. 개인에게 **공개된 공식 REST API** — 문서·예제가 공개되어 있다
2. **Windows·HTS 없이** 리눅스 클라우드 VM에서 24시간 운영 가능
3. **모의투자 서버가 별도로 존재** — 실계좌 전에 진짜 API로 검증할 수 있다

> 3번이 결정적이다. 모의투자 없이 실계좌로 바로 가는 건 브레이크 확인 없이 고속도로에 올라가는 것과 같다.

## 3. 권장 경로

```
지금 ──► [A] paper 모드로 전략·엔진 개발          (계좌 불필요)
          │
          ├─► [B] KIS 계좌 개설 → kis-paper 모의투자로 실전 검증
          │        └─► 검증 끝나면 kis-live 소액 운영
          │
          └─► [C] 메리츠 API 출시 확인
                   └─► meritz.spec.json 작성 → doctor → 모의 성격의 소액 검증 → 이관
```

전략·리스크·운영 코드는 **[A]에서 만든 것을 그대로 [B]와 [C]에 쓴다.**
증권사 교체 비용은 어댑터 하나뿐이며, 그게 이 구조를 택한 이유다.

메리츠 계좌를 주력으로 쓰고 싶다면 **[B]를 건너뛰고 [C]를 기다리는 것도 합리적**이다.
다만 그 기간에도 [A]로 전략을 다듬어 두면, API가 열렸을 때 바로 검증 단계로 들어갈 수 있다.
