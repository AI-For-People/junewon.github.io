# 운영 체크리스트

자동매매는 "만들어서 켜 두는 것"이 아니라 **매일 확인하는 것**이다.

## 가동 전 (1회)

- [ ] `make doctor` 오류 0건
- [ ] `.env` 권한 `600`, git에 올라가지 않았는지 확인 (`git status`)
- [ ] `AUTOTRADE_FEE_RATE` / `AUTOTRADE_SELL_TAX_RATE`를 **본인 계좌 실제 요율**로 교체
- [ ] `data/krx_holidays.txt`를 올해 KRX 공식 공지와 대조
- [ ] 호가단위 테이블(`pricing.py`)이 현행 규정과 일치하는지 확인
- [ ] 한도 3종을 **"오늘 이만큼 잃어도 괜찮은가"** 기준으로 설정
  - `AUTOTRADE_MAX_ORDER_NOTIONAL` / `AUTOTRADE_MAX_POSITION_NOTIONAL` / `AUTOTRADE_DAILY_LOSS_LIMIT`
- [ ] 킬 스위치 발동·해제를 **직접 해 본다** (`make kill` → `make doctor` → `make unkill`)
- [ ] 서버 시각 동기화(NTP) 확인
- [ ] 프로세스가 죽었을 때 재시작 여부 결정 — **자동 재시작은 신중히**
      (죽은 이유가 버그면 재시작이 사고를 반복시킨다)

## 매일 장 시작 전

- [ ] 전날 감사 로그 확인: `grep '"event":"order' var/journal.jsonl | tail -20`
- [ ] 차단 사유 확인: `grep 'order.blocked' var/journal.jsonl | tail`
- [ ] 킬 스위치가 내려가 있는지 (`ls var/KILL_SWITCH`)
- [ ] 오늘이 휴장일인지 (`python3 -m autotrade.cli doctor` 의 장 상태)
- [ ] 예수금·보유 종목이 예상과 일치하는지 (`cli balance`)

## 장중

- [ ] 주문 알림이 오면 **로그의 근거(reason)와 실제 시세를 대조**
- [ ] 이상하면 먼저 멈춘다: `make kill` → 원인 파악 → `make unkill`
- [ ] 같은 종목·방향 주문이 반복되면 즉시 중단 (전략 진동 신호)

## 매주

- [ ] 실제 체결가 vs 백테스트 가정 비교 — 차이가 크면 슬리피지 가정을 올린다
- [ ] 수수료·세금 누적액 확인 — 회전율이 성과를 갉아먹고 있는지
- [ ] 감사 로그 백업 (컨테이너·VM은 사라진다)

## 사고 대응

| 상황 | 즉시 조치 |
|---|---|
| 의도치 않은 주문 | `make kill` → 증권사 앱에서 미체결 취소 → 로그 확인 |
| 앱키 유출 의심 | 증권사에서 **앱키 폐기 → 재발급**, `.env` 교체, 로그 점검 |
| 계좌 잔고 불일치 | 즉시 중단. 증권사 거래내역이 정답. 로그와 대조해 원인 규명 |
| API 인증 실패 반복 | 토큰 캐시 삭제(`rm var/kis_token.json`) 후 1회 재시도. 반복되면 중단하고 증권사 문의 |
| 손실 한도 발동 | **당일은 재가동하지 않는다.** 다음 날 로그를 전부 읽고 원인을 찾은 뒤 결정 |

> 마지막 항목이 가장 중요하다. 손실 한도가 걸린 날 킬 스위치를 풀고 재가동하는 것이
> 자동매매에서 가장 흔한 파멸 경로다. 한도는 지키려고 만든 것이다.
